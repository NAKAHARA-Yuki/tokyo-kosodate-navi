# 世帯要件はどう書かれているか（issue #125 の実測）

計測: `scripts/survey_household_conditions.py`（dev, 7,812件に対して実行）
日付: 2026-08-18

## 結論を先に

**issue #125 が挙げた「1,334件（17.1%）で所得より大きい塊」は、そのままの意味では成立しない。**

新しい属性を持つことで判定できるようになるのは **292件（全体の 3.7%）** で、
所得（833件・#76）より小さい。#125 の優先度は下げてよい。

| | 件数 | 割合 |
|---|---:|---:|
| 世帯の語を含む（#125 の一次判定） | 1,334 | 17.1% |
| └ 制度名・課税世帯を伏せると消える | 242 | 18.1% |
| └ 伏せても世帯の語が残る | 1,092 | 81.9% |
| 　└ ひとり親（**#77 で判定済み**） | 260 | |
| 　└ 子どもの人数（**#75 で対応済み**） | 209 | |
| 　└ **それ以外＝新しい属性が要るもの** | **292** | **3.7%** |

## 1. 一次判定の 18.1% は世帯要件ではない

`世帯|同居|扶養|生計` で引くと、**制度の名前**と**所得の条件**が混ざる。

```
児童扶養手当 / 特別児童扶養手当     ← 「扶養」は制度名の一部。世帯構成の条件ではない
住民税非課税世帯 / 課税世帯         ← 所得の条件。#76 の担当範囲
```

これは #128 のレビューで見つかったものと同じ型の問題で、
**行政の制度名は条件語そのものでできている**（`児童扶養手当` `乳幼児医療費助成` `義務教育就学児医療費助成`）。
キーワードで数えるときは、制度名を伏せてから数える必要がある。

## 2. 1,334件は 93スキームしかない

```
異なる scheme_id            93
制度名の上位   児童手当 118 / 児童扶養手当 50 / 幼保無償化 36 / 特別児童扶養手当 35
```

**1,334件は「1,334通りの要件」ではなく、同じ制度が自治体ごとに複製されたもの。**
上位3つ（児童手当・児童扶養手当・特別児童扶養手当＝203件）は、
上の 1. でいう制度名の誤検出か、すでに判定できているものにあたる。

件数の大きさをそのまま「効きの大きさ」と読むと判断を誤る。

## 3. 書き方の分類（1,092件・重複あり）

| 分類 | 件数 | 割合 |
|---|---:|---:|
| C 扶養・養育している | 438 | 40.1% |
| A 同居・別居 | 377 | 34.5% |
| D ひとり親・父母の状況 | 349 | 32.0% |
| E 世帯人数・多子 | 212 | 19.4% |
| G 扶養義務者・親族 | 141 | 12.9% |
| B 生計同一 | 96 | 8.8% |
| F 世帯全員が〜 | 33 | 3.0% |
| H どれにも当たらない | 300 | 27.5% |

### A・C の大半は「利用者なら必ず満たす」条件

```
対象児童と同居する保護者
児童を養育している父または母
保護者と生計を一にする者
```

**このサービスの利用者は、子どもと同居して養育している人**なので、
これらを属性として持っても**誰も絞り込めない**。判定に使う価値がほとんどない。

「同居」の相手を数えると、識別に使えるものは多くない。

| 同居の相手 | 件数 |
|---|---:|
| その他・不明 | 189 |
| 子ども | 171 |
| **未成年後見人（児童手当の定型文）** | 118 |
| 配偶者・父母 | 33 |
| 親族・祖父母 | 8 |

118件は児童手当の「お子さんを養育している父母、または未成年後見人の場合」という
定型文が 118自治体に複製されたもので、要件ですらない。

### D・E はすでに持っている

- **D ひとり親** → `is_single_parent`。#77 で判定に使えるようになっている
- **E 多子・第2子** → 子どもの人数。#75 で複数の子を持てるようになっている

### G は所得の話

```
請求者又は扶養義務者の前年の所得が基準額を超えている方は対象外
扶養親族等に特別扶養親族があるときは限度額に加算
```

**「扶養義務者」「扶養親族」は所得制限の計算単位**として出てくる。
#76 の「⑥ 扶養人数で変わる（42件）」と同じもので、世帯構成の属性ではない。

## 4. 新しい属性が要るのは 292件

ひとり親でも子どもの人数でもない世帯要件だけを持つものが 292件（全体の 3.7%）。
中身を見ると、さらに性質が分かれる。

```
妊婦の同居者、妊娠を希望する女性（19歳以上）の同居者     ← 風しん予防接種
   利用者本人ではなく「同居している別の人」が対象

障害のある児童を扶養している保護者                     ← 児童育成手当（障害手当）
   has_disability で判定済み

本人、配偶者又は扶養義務者の所得が基準額を超えている方     ← 障害児福祉手当
   所得（#76）

保護者とその同居の家族の就労等により保育が困難な児童       ← 病児保育
   就労（#126）
```

**風しん予防接種の「妊婦の同居者」は、いまのデータモデルで表せない唯一の型。**
「利用者の属性」ではなく「同じ世帯にいる別の人の属性」を条件にしている。
ただしこれは世帯構成というより、**制度の対象者が親でも子でもない**という話で、
属性を増やすより「対象者が誰か」を持つほうが素直。

## 5. どうするか

**#125 は「世帯構成を属性として持つ」ではなく、次の3つに分けたほうがよい。**

1. **やらない**: A・C（同居・扶養）— 利用者なら必ず満たすので絞り込めない
2. **#76 に寄せる**: G（扶養義務者・扶養親族）— 所得制限の計算単位
3. **別issue**: 「制度の対象者が親／子／同居者のどれか」を持つ（風しん予防接種の型）

**いま新しく持つべき世帯属性は無い**というのがこの調査の結論。
所得（#76・833件）と就労（#126・345件のうち291件が所得と重ならない）を先にやるほうが効く。

## 測り直すとき

```bash
python scripts/survey_household_conditions.py
```

元データが更新されると数字は動く。**割合ではなく「制度名を伏せたか」「scheme で数えたか」**を
必ず確認すること。伏せずに数えると 1,334件、伏せると 1,092件、
実質は 292件と、見え方が4倍違う。
