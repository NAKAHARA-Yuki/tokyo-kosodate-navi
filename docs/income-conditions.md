# 所得条件はどう書かれているか（実測）

- 計測日: 2026-08-13
- 対象: dev（`gov_knowledge_db_dev`）の `benefits` 全 7,812 件
- 関連: [#76](https://github.com/NAKAHARA-Yuki/tokyo-kosodate-navi/issues/76)、
  [ADR 0001](adr/0001-judgment-vs-llm-separation.md)、[ADR 0002](adr/0002-age-inference.md)

## なぜ測ったか

所得条件を機械判定できるようにしたい（#76）。ただし年齢（ADR 0002）と違って
書き方の幅が大きいと分かっていたため、**規則で書ききれるのかを先に測った。**

対象は `conditions_text` と `target_persons_text` を連結した文字列に
`所得` `課税` `収入` `年収` のいずれかを含む **833 件（全体の 10.7%）**。

## 結果

書き方は7種類に分類できた（1件が複数に該当するため合計は 100% を超える）。

| 分類 | 件数 | 割合 | 機械判定 |
|---|---:|---:|---|
| ① 金額が本文に書いてある | 268 | 32.2% | できる |
| ② 住民税の課税/非課税・所得割 | 283 | 34.0% | できる |
| ③ **他制度の受給が条件** | 224 | 26.9% | **数値ではない**（後述） |
| ④ 生活保護の受給 | 209 | 25.1% | できる |
| ⑤ 所得制限・限度額（額は別表） | 214 | 25.7% | **本文に額が無い** |
| ⑥ 扶養人数で変わる | 42 | 5.0% | 扶養人数を持てば可能 |
| ⑦ 所得区分・階層 | 8 | 1.0% | 区分の定義が要る |
| ⑧ どれにも当たらない | 93 | 11.2% | — |

**何らかのパターンに掛かったのは 740 / 833（88.8%）。**
つまり**書き方の「型」は数えられる程度しかない。** 難しいのは型ではなく値のほうだった。

### いちばん重要な数字

**しきい値が本文に存在しないものが 408 件（49.0%）ある。**
①（金額の明示）にも②（住民税の課税区分）にも当たらないもの。

```
・保護者の所得が限度額を超えないこと（所得限度額表については下記リンクをご覧ください）
```

額は別ページの表にある。**これは抽出方法の問題ではない。** 正規表現でも LLM でも、
本文に無い数値は取り出せない。約半数はこの形である。

## ③ 他制度の受給が条件 — 数値ではなく関係

224 件（26.9%）が、金額ではなく**別の制度を受けていること**を条件にしていた。

```
[ひとり親家庭高校卒業程度認定試験合格支援事業]
  児童扶養手当の支給を受けているか、または同等の所得水準にある方

[母子家庭等高等職業訓練促進費等給付金]
  児童扶養手当を受給しているか、それと同等の所得水準の方

[母子・父子自立支援プログラム策定事業]
  児童扶養手当を受給しているか、または同様の所得水準であること
```

**児童扶養手当が所得審査の代理になっている。** 自治体が同じ審査を繰り返さないための
実務上の書き方で、利用者から見ても「児童扶養手当が通れば、この4つも通る」という
極めて有用な情報である。

これは所得額として抽出するものではなく、**制度から制度へのエッジ**である。
既存の `LEADS_TO`（`NEXT_STEP` / `SHARED_DOC`）とは別の関係にあたる。

- `SHARED_DOC` は「ついでに申請できる」＝同時に出せる
- これは「**先に受けていることが条件**」＝順序がある

エッジとして持てば「児童扶養手当が認定されたら、次はこの4つ」が辿れる。
グラフでしか表現できず、かつ利用者の利益に直結する数少ない例。

## ⑧ どれにも当たらない 93 件

```
[自立支援医療（育成医療）の給付] （所得に応じて費用負担があります。）
[保育料減額申請（収入減）] 世帯の直近3か月の平均収入額が、前年の平均収入月額より1割以上低額になったとき
[保育料減額申請（災害等）] その年に前年の所得額の10分の1を超える災害や盗難等による損失を生じたとき
```

- 1つ目は**条件ではない**（対象を絞っておらず、自己負担額の説明）
- 2つ目・3つ目は**時系列の比較**（過去との相対変化）で、静的な属性では判定できない

いずれも所得の値を持っても判定できない。**原文提示に倒す**（#63）べきもの。

## ここから導かれる方針

| 分類 | やること |
|---|---|
| ① ② ④ ⑥ | 規則で抽出する。書き方の型が限られており、`age_rules.py` と同じ方式で足りる |
| ③ | **数値にしない。制度間のエッジとして持つ**（別 issue） |
| ⑤ | 本文に額が無い。リンク先の限度額表を取り込むかどうかは別問題。当面は原文提示 |
| ⑦ ⑧ | 判定に使わない。原文提示（#63） |

**LLM を使うのは①②④⑥の同義表現の吸収に限られる**（「住民税非課税世帯」
「市町村民税所得割が非課税」「特別区民税が課されていない」が同じことを指す、など）。
全 833 件に当てるのではなく、規則で拾えなかった残りだけに当てる
（[ADR 0001 の追記](adr/0001-judgment-vs-llm-separation.md)の制約に従う）。

**「所得を属性として持てば判定できるようになる」は、実測では約半分にしか当てはまらない。**
残りは額が本文に無い（49.0%）か、そもそも数値の問題ではない（③⑧）。

## 実装した結果（2026-08-13）

`src/income_rules.py` に ①②④ の抽出を実装し、dev の全 7,812 件に当てた結果。

| ルール | 件数 |
|---|---:|
| `tax_non_taxable`（住民税非課税が要件） | 172 |
| `welfare_required`（生活保護の受給が要件） | 157 |
| `threshold_upper`（金額の上限） | 129 |
| `welfare_excluded`（生活保護受給者は対象外） | 37 |
| `tax_taxable`（住民税課税世帯が要件） | 18 |
| `threshold_lower_excluded`（「◯円以上は対象外」） | 14 |
| **合計** | **527** |

所得に言及する 833 件のうち **443 件（53.2%）** から抽出できた。
残り 84 件は「所得・課税・収入」の語を含まないが生活保護に言及していたもので、
分類の網から漏れていた分が追加で取れている。

**53.2% は、上で出した「しきい値が本文に無い 49.0%」とほぼ裏返しの数字**である。
本文に書かれているものはおおむね取れており、取れないものは本文に無い。

### 金額の基準を取り違えないこと

`income_basis` で「何の額か」を持つ。取り違えると桁が違う比較になる。

| basis | 件数 | 例 |
|---|---:|---|
| `tax_levy`（住民税所得割額） | 70 | 市民税所得割額が年額 77,100 円以下 |
| `income_tax`（**所得税額**） | 27 | 前年度の所得税の額が 8,400 円以下（入院助産） |
| `salary`（収入・年収） | 24 | 世帯年収約 360 万円未満相当 |
| `income`（所得） | 22 | 父母または養育者の所得が 4,596,000 円未満 |

**最初の実装は所得税額（8,400円）を「所得」として扱っていた。**
利用者の所得と比べれば全員が対象外になる。`income_basis` が揃わないものは
比較してはいけない。

### 取らなかったもの

向きが読み取れないものは抽出しない（`None` を返す）。

- 「世帯の所得が100万円以上の方」— 対象なのか対象外なのか本文から決まらない
- 「助成額は月額5,000円です」— 所得ではない金額
- 「世帯員の預貯金等資産の保有額が600万円以下」— 資産であって所得ではない
- 「住民税非課税世帯は対象外です」— 非課税が要件ではない

## 未反映（ETL の再実行が要る）

`benefits` テーブルへの列追加はコード側だけで、**dev のテーブルにはまだ列が無い。**
元データの取得元にコンテナから到達できず `make etl` を実行できないため
（issue #104 と同じ制約）。ネットワーク制限の無い環境で ETL を回した時点で反映される。
