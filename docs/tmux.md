# tmux チートシート

## tmux とは何か、なぜ使うのか

SSH でサーバーに繋いで作業していると、**接続が切れた瞬間に実行中のプログラムも死にます**。
電車で圏外に入った、ノートPCを閉じた、Wi-Fi が切り替わった——それだけで作業が飛びます。

tmux はサーバー側に「ターミナルの部屋」を作っておく道具です。
部屋の中でプログラムを動かしておけば、**あなたが部屋を出ても中の作業は動き続けます**。
あとで入り直せば、出ていったときの続きがそのまま表示されます。

このプロジェクトでは Claude Code を tmux の中で動かしっぱなしにします。
そうすることでスマホから接続しても、朝までかかる作業を仕掛けて放置しても、途中で消えません。

用語は3つだけ覚えれば足ります。

| 用語 | 意味 |
|---|---|
| **セッション** | 「部屋」。これが生き残る単位。名前を付けて管理する |
| **アタッチ** | 部屋に入ること |
| **デタッチ** | 部屋から出ること。**中の作業は動き続ける** |

## 最初に覚える操作はこれだけ

```bash
tmux new -s claude       # claude という名前の部屋を作って入る
```

```
Ctrl-b   を押して離してから   d      ← 部屋から出る（作業は生き続ける）
```

```bash
tmux attach -t claude    # 部屋に入り直す
```

**この3つで9割の用が足ります。**

## prefix キーという考え方

tmux への命令は、必ず **`Ctrl-b` を押してから、指を離して、次のキー**を押します。

```
Ctrl-b  →（指を離す）→  d
```

`Ctrl-b` と `d` を同時押しするのではありません。「これから tmux に話しかけます」という
合図が `Ctrl-b` で、その後のキーが命令の中身です。この `Ctrl-b` を **prefix** と呼びます。

以下の表で `Ctrl-b d` と書いてあるものはすべてこの押し方です。

## セッション操作

| やりたいこと | コマンド / キー |
|---|---|
| 部屋を作って入る | `tmux new -s claude` |
| 部屋から出る（作業は継続） | `Ctrl-b` `d` |
| 部屋に入り直す | `tmux attach -t claude` |
| 部屋の一覧を見る | `tmux ls` |
| 部屋を選んで入る（一覧から） | `Ctrl-b` `s` → 矢印で選んで Enter |
| 部屋の名前を変える | `Ctrl-b` `$` |
| 部屋を完全に消す | `tmux kill-session -t claude` |

`tmux attach` は `tmux a` と短く書けます。

> **入り直したのに何も無い**場合、部屋の名前が違うかもしれません。
> `tmux ls` で一覧を確認してください。

## ウィンドウ（タブのようなもの）

1つの部屋の中でタブを切り替える感覚です。Claude Code を動かしたまま、
別のタブでログを見る、といった使い方をします。

| やりたいこと | キー |
|---|---|
| 新しいタブを開く | `Ctrl-b` `c` |
| 次のタブ / 前のタブ | `Ctrl-b` `n` / `Ctrl-b` `p` |
| 番号で移動 | `Ctrl-b` `0`〜`9` |
| タブに名前を付ける | `Ctrl-b` `,` |
| タブを閉じる | そのタブで `exit` |

タブの一覧は画面下のバーに出ています。`*` が付いているのが今いるタブです。

## ペイン（画面分割）

1つのタブを分割して並べて見られます。

| やりたいこと | キー |
|---|---|
| 左右に分ける | `Ctrl-b` `%` |
| 上下に分ける | `Ctrl-b` `"` |
| 隣に移動 | `Ctrl-b` `←` `→` `↑` `↓` |
| 分割を閉じる | そのペインで `exit` |
| 今のペインを最大化 / 戻す | `Ctrl-b` `z` |

`Ctrl-b z` は覚えておくと便利です。分割したまま一時的に1つを大きく見られます。

## 画面をさかのぼって読む（重要）

**tmux の中ではマウスのスクロールがそのままでは効きません。** 初心者が最初に必ず詰まる箇所です。
過去の出力を読むには「コピーモード」に入ります。

```
Ctrl-b  [        ← コピーモードに入る
```

入ったら矢印キー、`PageUp` / `PageDown` でさかのぼれます。読み終わったら `q` で戻ります。

| やりたいこと | キー |
|---|---|
| コピーモードに入る | `Ctrl-b` `[` |
| さかのぼる / 進む | `↑` `↓` または `PageUp` `PageDown` |
| 文字を検索する | コピーモード中に `/` → 語句 → Enter |
| コピーモードを抜ける | `q` |

> **抜けるのを忘れると入力を受け付けません。** 「キーを打っても反応しない」ときは、
> たいていコピーモードに入ったままです。`q` を押してください。

## このプロジェクトでの使い方

```bash
# サーバーに入る
ssh <サーバー>

# 部屋を用意する（初回だけ。2回目以降は attach）
tmux new -s claude

# コンテナに入って Claude Code を起動
make agent-shell
claude --dangerously-skip-permissions --remote-control kosodate

# 出る（Claude Code は動き続ける）
Ctrl-b  d
```

次からはこうです。

```bash
ssh <サーバー>
tmux attach -t claude
```

```
ssh server
 └─ tmux（部屋。ここが生き残る）
      └─ make agent-shell（コンテナに入る）
           └─ claude --dangerously-skip-permissions --remote-control
```

**tmux はホスト側で動かします。** コンテナの中ではありません。
コンテナを作り直しても部屋が残り、作業の履歴が消えないためです。

### スマホから使う

- **Claude アプリから** — `--remote-control` を付けて起動してあれば、アプリ側から
  そのセッションに指示を送れます。tmux の操作は不要です
- **SSH アプリから**（Termius など）— 上と同じく `tmux attach -t claude` で入ります。
  画面が狭いので `Ctrl-b z` でのペイン最大化が効きます

### セッションに繋がらなくなったとき

**まず再起動しないでください。** 見た目が同じでも原因は2つあり、対処が違います。
慌てて作り直すと、残っているはずの会話の履歴を捨てることになります。

最初に切り分けます。**ホスト側で**実行してください。

```bash
tmux ls
```

| 結果 | 状態 | 対処 |
|---|---|---|
| 部屋の一覧が出る | 接続だけが切れている | **A** へ |
| `no server running` | 部屋ごと消えている | **B** へ |

#### A. リモートコントロールだけが切れている

アプリに **「リモートコントロールセッションがオフラインです」** と出ている状態です。

**Claude Code は死んでいません。** 切れているのは claude.ai との接続だけで、
tmux の部屋も、コンテナも、その中の作業も動き続けています。会話の履歴もそのままです。

部屋に入り直します。

```bash
tmux attach -t claude
```

Claude Code の入力欄で次を実行し、`Enable Remote Control` を選びます。

```
/remote-control
```

新しい URL が表示されるので、**それを開きます。**

```
/remote-control is active · https://claude.ai/code/session_xxxxx
```

> **アプリの一覧には出てきません。**
> `/remote-control` は実行のたびに新しいセッションIDを発行しますが、
> それがアプリの Code タブの一覧に並ぶとは限りません。
> 古い画面をリロードしても、失効したIDを見続けるだけで戻りません。
> **URL を直接開くのが確実な唯一の方法です。**

#### B. tmux の部屋ごと消えている

`tmux ls` が `no server running` を返す場合です。サーバーを再起動したときや、
tmux を使わずに `make agent-shell` していた場合に起こります。

**このセッションには戻れません。** コンテナの中では Claude Code のプロセスが
まだ動いていますが、キーボードを繋ぐ先（pty）を失った「孤児」の状態で、
入力を届ける方法がありません。

**ただし会話の履歴は残っています。** `~/.claude` に書き出されているので、
別のセッションから読み直せます。

まず孤児プロセスを止めます。**これを飛ばさないでください。**
生かしたまま次を始めると、同じ履歴ファイルを2つのプロセスが掴んで壊れます。

```bash
docker exec kosodate-agent-<ユーザー名> sh -c 'ps -eo pid,cmd | grep "[c]laude/versions"'
docker exec kosodate-agent-<ユーザー名> kill <PID>
```

そのうえで、**tmux の中から**入り直します。

```bash
tmux new -A -s claude
make agent-shell
claude --resume
```

`--resume` で過去の会話の一覧が出ます。**更新時刻が新しいもの**を選べば、
文脈を引き継いだ状態で再開できます。あとは `/remote-control` を打てば
スマホからも繋がります。

> **孤児プロセスは、気づかれないまま動き続けていることがあります。**
> `--dangerously-skip-permissions` で起動していると、誰も画面を見ていない間も
> 作業を続けます。再開したら、身に覚えのない結果が出ていないか確認してください。
>
> ```bash
> gh pr list --author "@me" --state all --limit 10
> ```

#### 誰かに代わりに操作してもらうとき

**入力欄に打ちかけのテキストが残っていないか、先に確認してもらってください。**
残ったまま送ると文字列が連結され、壊れた入力になります。

```bash
tmux capture-pane -p -t claude | tail -6     # 入力欄が空かを見る
```

他人の tmux は `sudo -u <ユーザー名> tmux ...` で操作できますが、
**出てきた URL はそのセッションの持ち主にだけ渡してください。**
セッションへのアクセス権そのものです。

## 困ったときは

| 症状 | 原因と対処 |
|---|---|
| キーを打っても反応しない | コピーモードのまま。`q` で抜ける |
| マウスでスクロールできない | 仕様。`Ctrl-b` `[` でコピーモードに入る |
| `Ctrl-b` が効かない | 二重に tmux に入っているかも。`tmux ls` で確認 |
| attach したら「no sessions」 | 部屋がまだ無い。`tmux new -s claude` で作る |
| 「sessions should be nested」と出る | すでに tmux の中にいる。`Ctrl-b` `d` で一度出る |
| 画面が崩れた | `Ctrl-b` `d` で出て入り直す |
| アプリに「リモートコントロールがオフライン」 | 接続だけが切れている。**再起動しない。**上の **A** |
| `tmux ls` が `no server running` | 部屋ごと消えている。孤児プロセスを止めて `claude --resume`。上の **B** |
| どの部屋にいるか分からない | 画面下のバー左端に名前が出ている |

## 覚えるべき最小セット

これだけで始められます。困ったらこのページに戻ってください。

```
tmux new -s claude       部屋を作る
tmux attach -t claude    部屋に入る
tmux ls                  部屋の一覧

Ctrl-b  d                出る（作業は継続）
Ctrl-b  [                さかのぼって読む（q で戻る）
Ctrl-b  c                タブを開く
Ctrl-b  z                今の画面を最大化 / 戻す
```
