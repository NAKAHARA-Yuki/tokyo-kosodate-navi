# 「他制度を受けていること」はエッジにできるか（issue #124 の実測）

計測: `scripts/survey_requires_benefit.py`（dev, 7,812件に対して実行）
日付: 2026-08-18

## 結論を先に

**エッジにできる。ただし「受けていないことが条件」がほぼ同数あり、そちらを取り違えると
判定が逆になる。**

```
他制度を受けて**いる**ことが条件    162 件
他制度を受けて**いない**ことが条件   151 件   ← 文の形がほとんど同じ
```

そして **引けるエッジはほぼ1種類**。児童扶養手当がハブになっている。

```
参照 196本のうち 145本（74%）が 児童扶養手当
同じ自治体の制度に解決できた       154 / 196（79%）
```

## 1. 児童扶養手当ひとつがハブ

| 前提として挙げられる制度 | 参照数 |
|---|---:|
| **児童扶養手当** | **145** |
| 心身障害者福祉手当 | 5 |
| 特別児童扶養手当 | 2 |
| その他（各1〜2） | 〜10 |

`REQUIRES_BENEFIT` という汎用のエッジ型を作っても、**実質は児童扶養手当からの
放射状のエッジ**になる。issue #124 の見立て（「児童扶養手当が所得審査の代理になっている」）は
そのとおりだった。

### 下流（芋づるの中身）

```
ひとり親家庭自立支援教育訓練給付金
ひとり親家庭高等職業訓練促進給付金
ひとり親家庭高等学校卒業程度認定試験合格支援事業
都営交通無料乗車券
```

**自治体あたり 中央値3件・最大11件・平均3.4件。**
ひとり親の方が児童扶養手当に認定されると、平均3.4件が芋づる式に申請できるようになる。

これは「貰いそびれ」に直接効く。**児童扶養手当の認定を1回通せば、
そこから3件前後の申請可能な制度を提示できる。**

## 2. いちばん危ないのは否定条件

同じ「〜給付金を受けて…」という形で、意味が逆のものが 151件ある。

```
肯定   児童扶養手当の支給を受けている方
否定   過去にこの給付金を受けたことがない方
       当該事業と趣旨を同じくする給付を受給していない方
```

**否定を肯定として拾うと、「その制度を受けた人にだけ出す」べきものが
「受けた人には出さない」制度に化ける。** 高等職業訓練促進給付金のように、
**同じ制度文の中に肯定（児童扶養手当を受けている）と否定（過去にこの給付金を受けていない）が
両方書かれている**ものがあるので、文単位で見る必要がある。

`age_rules.py` の教訓（制度名が条件語そのものでできている）と同じく、
**エッジを引く前に否定の判定を先に通すこと。**

## 3. 名前から制度を引けない参照が 21%

```
解決できなかった 42 / 196
  心身障害者福祉手当     3   ← その自治体には別名で存在するか、そもそも無い
  修了支援給付金        2   ← 制度の一部（給付金の名前ではない）
  中央区児童育成手当     2   ← 自治体名が付いていて title と一致しない
  児童の障害により障害手当  2   ← 文の断片。制度名ではない
```

**同じ自治体に同名がある場合だけエッジを引く**方針にすれば、
21%は引けないが誤ったエッジも作らない。**引けない分は条件原文の提示に倒す**（#63）のが、
このリポジトリの既存の方針と揃う。

## 4. 提案する形

```
benefit_requires_benefit(from_benefit_id, to_benefit_id, relation, evidence)
  relation = 'REQUIRES_BENEFIT'   ← 受けていることが条件
           | 'EXCLUDED_BY_BENEFIT' ← 受けていると対象外
```

**否定も同じテーブルに `relation` を変えて持つ。** 別テーブルにすると、
片方だけ実装して逆の意味を見落とす事故が起きやすい。

`evidence` に抽出元の文を残す（`income_rules.py` と同じ方式）。

### 既存のエッジとの違い

| relation | 意味 | 順序 |
|---|---|---|
| `SHARED_DOC` | 同じ書類で申請できる | 無し |
| `NEXT_STEP` | 年齢帯が地続き | 年齢の前後のみ |
| **`REQUIRES_BENEFIT`** | **先に認定が要る** | **申請の前後** |

`NEXT_STEP` は年齢が地続きなだけで根拠が弱い（#121）。
`REQUIRES_BENEFIT` は**条件文に書いてある**ので根拠が強い。

## 5. 判定に使うときの注意

**「児童扶養手当を受けている」かどうかは利用者の属性であって、制度データではない。**
これを判定に使うには #31（利用履歴）が要る。

利用履歴が無い段階でも、**「児童扶養手当が認定されたら、次はこれが申請できます」という
提示**には使える。判定（絞り込み）ではなく導線として先に出せる。

## 測り直すとき

```bash
python scripts/survey_requires_benefit.py
```

**肯定と否定の件数を必ず両方見ること。** 肯定だけ数えると「162件のエッジが引ける」に見えるが、
同じ形の否定が 151件ある。
