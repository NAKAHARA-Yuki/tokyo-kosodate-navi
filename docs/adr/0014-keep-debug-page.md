# ADR 0014: `/debug` を開発用画面として残す

## ステータス

採用（2026-08-02）

## 背景

ADR 0013 でフロントエンドを Next.js の別サービスに分離したとき、旧画面
（`frontend/public/debug.html`、素の HTML + cytoscape.js）は `/debug` に退避して残した。

当初は「新画面への機能移植が終わったら撤去する」計画だった。しかし旧画面には
新画面に無いものが揃っている。

- ナレッジグラフそのものの可視化（制度・条件・書類・スキルツリー）
- ライフステージ別のタイムライン
- 属性での絞り込み
- Gemini によるやさしい解説

これらは新画面へ順次移植していくが（#54 / #55 / #56）、移植後も
**「BigQuery に入っているグラフが実際どうなっているか」を素で見られる画面**には
別の価値がある。データモデルを変えたときの確認や、デモでの説明に使える。

## 決定

**`/debug` は撤去しない。開発・デモ用の画面として残す。**

そのうえで、正式な画面と取り違えられないようにする。

1. 画面上部に「この画面は開発用です」と明示し、正式な画面へのリンクを置く
2. `<meta name="robots" content="noindex, nofollow">` を付け、検索結果に出さない
3. 新画面から `/debug` への導線は張らない
4. フォントと基本配色はデジタル庁デザインシステムのトークンの値に合わせ、
   新画面と極端に違う見た目にはしない
5. 実データの制度情報を表示する以上、免責の一文を入れる

## やらないこと

- **デジタル庁デザインシステムのコンポーネントによる作り直し。**
  この画面はビルド工程を持たない素の HTML であることに価値がある
  （cytoscape を直接触れる、1ファイルで完結する）。
  デザイントークンは**値をコピーして合わせるだけ**にとどめ、パッケージは取り込まない
- **アクセシビリティ対応（#58）。** 開発用画面のため対象外とする
- **出典表示の作り込み（#57）。** 免責の一文だけで足りる

## 結果

受け入れる負債:

- **cytoscape が2経路で入る。** 旧画面は `frontend/public/cytoscape.min.js` を自前配布
  （ADR 0010）、新画面は npm。版がずれうるので、`frontend/public/README.md` の記録を
  更新するときに npm 側の版も見ること
- **素の JS と Next.js の二重メンテ。** 旧画面は現状維持とし、新画面の変更に
  追従させることはしない。ただし旧画面向けの E2E は残し、壊れたら気づけるようにする
