# ADR 0002: 対象年齢を正規表現で推定し、明示値とは別カラムに保持する

- ステータス: 採用
- 日付: 2026-07-25

## 背景

属性マッチングの主軸は「子どもの年齢」だが、元データで年齢が構造化されているのは
**7,812件中 2,794件（36%）だけ**だった。残り64%は

- 「小学校就学前まで」
- 「3歳児健康診査」
- 「18歳に達する日以後の最初の3月31日まで」

のように**文章の中にしか年齢が書かれていない**。

この状態で `min_age_months IS NULL OR min_age_months <= @age` という条件で絞ると、
NULL の6割超が全て素通りする。実際、10歳で検索すると「こんにちは赤ちゃん訪問」
「BCGワクチン」といった新生児向けの制度が並んでいた。
**年齢での絞り込みが事実上機能していなかった。**

## 決定

**正規表現ルール（`src/age_rules.py`）でテキストから年齢を推定する。LLM は使わない。**

推定値は明示値を上書きせず、別カラムに保持する。

| カラム | 内容 |
|---|---|
| `min_age_months` / `max_age_months` | 元データに明示されていた値（変更しない） |
| `inferred_min_age_months` / `inferred_max_age_months` | 推定値 |
| `effective_min_age_months` / `effective_max_age_months` | 明示値を優先し、無ければ推定値。**絞り込みはこれを使う** |
| `age_source` | `explicit` / `inferred` / `corrected` / `unknown` |
| `age_inference_rule` | どのルールで推定したか |

UI では `age_source='inferred'` のとき「（推定）」と明示し、断定的に見せない。

## 理由

### なぜ LLM ではないのか

[ADR 0001](0001-judgment-vs-llm-separation.md) の通り。加えて、7,812件を LLM に通すと
コストと時間がかかり、結果が再現しないため回帰テストも書けない。
正規表現なら単体テストで永続的に品質を担保できる。

### なぜ明示値を上書きしないのか

推定は必ず外す。上書きすると「元データはどうだったか」が失われ、
推定ロジックを改善したときに検証できなくなる。分離しておけば
`age_source` 別に精度を測れるし、推定を無効化することもできる。

## 実装上の要点

**ルールの評価順序が精度を決める。** 具体的な記述から順に評価する:

1. 数値レンジ（`3歳から5歳`、`生後2か月から7か月`、`生後5日から7日`）
2. 学年レンジ（`小学校6年生から高校1年生`）
3. **義務教育就学期** → **就学前**（`小学校入学前`、`就学前`、`未就学`）
4. 定型文（`18歳に達する日以後の最初の3月31日`、`18歳に到達した年度末`）
5. 単一境界（`3歳未満`、`18歳以下`）
6. 「X歳児」「Xか月児」（`3～4か月児` `0～2歳児クラス` のレンジを先に見る）
7. 学齢（`小学生`、`中学生`、`高校生`）
8. 発達段階語（`新生児`、`乳児`、`幼児`）→ `生後N日未満`

> ⚠️ **3 を 7 より先に評価しないと破綻する。**
> 「小学校入学前」は文字列 `小学` を含むため、学齢判定を先に置くと
> 小学生（72〜143ヶ月）と誤判定する。実装当初これを踏んだ。
>
> **順序だけでなく、3 のパターンが実データの言い回しを網羅しているかも要る。**
> 「前」で終わる形しか見ておらず、**「小学校に入学するまで」を取りこぼしていた**（#107）。
> 順序は正しかったのに 3 に一致せず 7 に落ちるため、症状は順序を壊したときと同じになる。
> dev で 62件が誤判定していた（すべて妊娠期の制度）。パターンを足すときは
> 「まで」「前」の両方を意識すること。

妊娠期の制度は子の月齢で表現できないため、`is_prenatal` フラグとして別軸で持つ。

## 帰結

- 年齢で絞り込める制度が **36% → 66%** に増加
- 10歳で検索したときに対象年齢を超えた制度が **0件** になった（修正前は多数混入）
- 推定精度は `age_inference_rule` 別に検証でき、テストで回帰を防げる

### 残るリスク

- 推定が外れる制度は依然存在する。だから `age_source` を UI に出している
- `unknown`（2,672件）は年齢で絞れない。現状は「年齢条件の記載なし」として
  末尾に並べ、取りこぼし（＝知りそびれ）を防ぐことを優先している

## 追記（2026-08-13）: `age_source` の見せ方（issue #61）

上の「残るリスク」で **「だから `age_source` を UI に出している」** と書いていたが、
**出していたのは旧 `/debug` だけだった。** 新しい Next.js の画面は `age_source` を
型では受け取りながら一度も使っておらず、対象年齢そのものが画面に出ていなかった。

### 実データでの確認（dev, 7,812件）

| `age_source` | 件数 | 割合 | 年齢範囲 |
|---|---:|---:|---|
| `explicit` | 2,794 | 35.8% | 必ず入っている |
| `inferred` | 2,346 | 30.0% | 必ず入っている |
| `unknown` | 2,672 | 34.2% | **両方 NULL** |

**6割超が「元データに年齢が書かれていない」制度**にあたる。

年齢で絞ったときに何が出るかも測った。`unknown` は範囲が NULL なので
`age_filter_sql()` を素通りし、**どの年齢でも必ず 2,672件が出る。**

| 絞り込み | 合計 | explicit | inferred | unknown |
|---|---:|---:|---:|---:|
| 0か月 | 5,341 | 1,410 | 1,259 | 2,672 |
| 5歳 | 5,240 | 1,533 | 1,035 | 2,672 |
| 10歳 | 4,537 | 1,212 | 653 | 2,672 |
| 20歳 | 3,218 | 511 | 35 | **2,672（83%）** |

年齢が上がるほど比率が上がり、20歳では結果の8割が「年齢条件を読み取れなかった制度」になる。

### 決めたこと

**1. 対象年齢を必ず出し、確度を文言で示す。**

| `age_source` | 表示 |
|---|---|
| `explicit` | `対象 3歳〜3歳11か月` |
| `inferred` | `対象 0か月〜3歳（推定）` |
| `unknown` | `対象年齢の記載なし`（**範囲は出さない**） |

`unknown` に「0か月〜」のような既定値を当てないこと。
**読み取れなかったという事実が消える。**

**色だけで区別しない。** 注意色は付けるが、文言だけでも区別がつくようにする
（WCAG 1.4.1。ADR 0016）。補足は `title` 属性に持たせる。

**2. `unknown` は絞り込みから外さない**（従来どおり）。

「対象なのに出ない」を作る方が害が大きい。ただし**確度の順に並べ**
（`AGE_SOURCE_ORDER_BY`）、上の表示で確認済みの条件と区別できるようにする。

上の 83% という数字を踏まえると、属性入力フォーム（#53）が入って
「自分の年齢で絞る」が主動線になった時点では、これだけでは足りない。
**別セクション（「年齢の条件が読み取れなかった制度」）に分けることを #53 で検討する。**
いまは一覧が年齢で絞られていないため、表示の明示で足りると判断した。

### 直したこと

- 一覧カードと詳細ページに対象年齢を表示（`frontend/components/age-chip.tsx`）
- **詳細 API が素の `min/max_age_months` を返していた**のを `effective_*` に修正。
  6割超が NULL の列で、そのまま出すと「記載なし」ばかりになるところだった
  （一覧は最初から `effective_*` を返しており、詳細だけがずれていた）
- E2E で explicit / inferred / unknown の3種類すべての表示を検証（スタブに unknown を追加）

## 追記（2026-08-13）: 対象者欄にある年齢を取りこぼしていた（issue #117）

`unknown` 2,672件の対象者欄（`target_persons_text`）を実際に読んだところ、
**現行ルールが拾えていない書き方が残っていた。** ETL は `targetPersons` を最初に見るので、
本来は拾える位置にある。

### 足したルール（dev で実測）

| ルール | 拾える表記 | 新規 | 既存の修正 |
|---|---|---:|---:|
| `stage_until_fiscal_year_end` | `18歳に到達した年度末` | 15 | 37 |
| `stage_preschool`（`未就学` を追加） | `未就学児` | 25 | 7 |
| `range_months_child` / `range_years_child` | `3～4か月児` `0～2歳児クラス` | 6 | 68 |
| `stage_compulsory_education` | `義務教育就学期` | 5 | 8 |
| `range_days` / `upper_days` | `生後5日から7日` | 6 | 13 |
| `child_age_months`（`Nか月のお子さん` を追加） | `概ね5か月のお子さん` | 3 | 1 |

**推定できた制度: 2,346 → 2,406件（+60）。`unknown` 2,672 → 2,612件。推定が消えたものは0件。**

いちばん効いたのは `18歳に到達した年度末` です。**児童扶養手当・児童育成手当・
ひとり親家庭等医療費助成**がこの表記で、対象年齢を一つも持てていませんでした。
「18歳に達する日以後の最初の3月31日」と同じ意味を「年度末」と書く自治体があるだけです。

### 順序の制約が3つ増えた

上の「3 を 7 より先に」と同じ型の話が3つ増えたので明記します。

| 先に見るもの | 後に見るもの | なぜ |
|---|---|---|
| `義務教育就学期` | 就学前 | 「就学」を含むが**就学後**（小1〜中3）。逆にすると 0〜5歳になる |
| — | — | ただし **`義務教育就学` だけで判定してはいけない**（下記） |
| `未就学` | 学齢 | #107 とまったく同じ。「小学校」を含む文と同じ扱いで 6〜11歳になっていた |
| `新生児` | `生後N日` | 日数の方が具体的だが、**日数は原則で例外はもっと広い** |

最後のものだけ「具体的な記述を先に」の原則と逆になっています。

```
原則として生後28日以内の新生児です。ただし、里帰り出産などで訪問を
受けられなかった場合には、生後4か月になる前日までお受けできます。
```

日数（0か月）に寄せると、**1か月の子に新生児訪問が出なくなります。**
25件が該当したため、段階語を優先しています。

### 段階語は「制度の名前」にも当たる（レビューで見つかった）

`義務教育就学` を前方一致で見ていたところ、**条件ではなく他制度の名前**に反応していた。

```
[ひとり親家庭等医療費助成制度]
  対象となる方   …児童が18歳に達した日以後の最初の3月31日まで…     ← 正しい記述
  対象外となる方 ・…、義務教育就学児医療費助成制度医療証、…を交付されている方  ← ここに当たっていた
```

さらに悪いことに、**`義務教育就学前` まで巻き込んでいた。**

```
[乳幼児医療費助成制度]
  市内に住所を有する義務教育就学前（6歳に達した日以降最初の3月31日）までの乳幼児
  → 0〜71か月であるべきところ 72〜191か月。0歳児にこの制度が出なくなる
```

dev で **6件**が誤判定だった（乳幼児医療費助成 5件・ひとり親家庭等医療費助成 1件）。
`義務教育就学(?:期|中)` と**期間を指す語まで**見る形に直している。

**段階語を足すときは「その語が制度の名前の一部になっていないか」を必ず見ること。**
医療費助成の制度名は `乳幼児` `義務教育就学児` `高校生等` と**そのまま年齢の段階語**でできており、
別制度の対象外条件として列挙されることが多い。

### レンジは全部の和を取る

`3～5歳児クラス及び住民税非課税世帯の0～2歳児クラス` のように、
1つの制度が複数のクラスを並べる書き方が多い（幼保無償化。dev で 37件）。
最初の1つだけを採ると 3〜5歳になり、**同じ制度の対象である0〜2歳児が漏れます。**

### 「Nか月」は子どもを指す語が付くものだけ拾う

`4～6か月のお子さん` は拾い、`妊娠8か月` は拾いません。
`unknown` 2,672件のうち **17件が「妊娠Nか月」を含んで**おり、
無条件に拾うと妊娠中の方に 8か月児向けの制度が出ます。

### 「年度末」の規則は、狭める変更でもある

`18歳に到達した年度末` を拾えるようにしたことで **12件が新しく年齢を持った**が、
同時に **24件が 0〜239か月 → 0〜227か月に狭まっている。**

```
18歳に達した年度末までの児童（中程度以上の障害を有する場合は20歳未満）
  変更前  0〜239か月（20歳未満）← 障害がある場合の**例外**を拾っていた
  変更後  0〜227か月（18歳年度末）← **本則**
```

**本則を採る判断でよい**が、これは「対象なのに出ない」を作りうる向きでもある。
19歳で障害のあるお子さんを持つひとり親には、児童扶養手当が出なくなる。
`is_prenatal` のように**別軸で持つべき条件**（障害の有無）を年齢に押し込んでいるのが原因で、
`has_disability` と組み合わせる形にするのが本筋（#76 / #78）。

`新生児` と `生後N日` のところに書いた「**日数は原則で、例外の方が広い**」と同じ物差しで、
ここでは逆に**原則を採って例外を落としている**。両方とも意図的な選択であることを明記しておく。

### 1つの欄に複数の対象区分が並ぶとき

規則は最初に一致したもので打ち切るため、**区分が並んでいると残りを捨てる。**

```
（2）MR2期未接種で、12歳となる日の属する年度の末日までの方
（3）MR2期未接種で、13歳となる日の属する年度の初日から20歳の誕生日の前日までの方
  → (2) だけを採ると 0〜155か月（12歳11か月）。**13〜19歳が丸ごと落ちる**
```

**箇条書きのマーカー（`（1）` `①` `(ア)`）で割って、全部の和を取る。**

括弧書きの例外（`（障害がある場合は20歳未満）`）は**同じ区分の中**にあるので和を取らない。
マーカーの有無で区別している。

### 年度末は上限とは限らない

```
育休対象の子が1歳になった年度末**から**1か月までが補助対象期間となります
  → 対象年齢ではなく補助**期間**。0〜23か月と読むと満3歳児向けの制度が 0〜1歳になる
```

`まで` `以前` まで見て、上限であることを確かめる。
`年度末（3月31日）まで` のように日付が挟まる形があるので窓を持たせるが、
**その窓に「から」が入ってはいけない。**

### 残っている取りこぼし（承知のうえ）

- `6・9か月児健診` は対象者欄に「受診票は3から4か月児健診の通知に同封されています」と
  書かれており、3〜9か月と読みます（本来は 6〜11か月）。**1件**
- `6～7か月・9～10か月の赤ちゃん` は後半しか拾えず 9〜10か月になります。**2件**
  （`6～7か月児・9～10か月児` と「児」が両方に付いていれば 6〜10か月と読めます）

いずれも1つの欄に複数の健診が並ぶ形で、**どれがこの制度の対象かはテキストからは決まりません。**

### まだ手を付けていないこと（#117 の本体）

`age_source` に4つ目の値を足して **「年齢の条件が無い」と「読み取れなかった」を区別する**
ところは、このまま残っています。`unknown` 2,612件のうち **842件は `is_prenatal=true`**（妊娠期）、
**826件は対象者欄そのものが空**で、性質が違うものが混ざったままです。
## 追記（2026-08-20）: 「元データの年齢欄は正しい」が成り立たない（issue #114）

この ADR の決定（**明示値を優先し、推定で上書きしない**）は、
「元データの年齢欄は正しい」ことを前提にしている。**dev で 10件、成り立たなかった。**

```
三鷹市  「3～4カ月児健康診査」  年齢欄 = 36〜71   ← か月を歳として登録している
青梅市  「5歳児虫歯予防教室」   年齢欄 = 5〜6     ← 歳を月として登録している
目黒区  「9から10か月児健診」   年齢欄 = 6〜7
```

`effective_*` は `explicit` をそのまま使うので、**誤った年齢欄が判定に入る。**
三鷹市の例では 0歳の子に3〜4か月児健診が出ず、3〜5歳の子に出る。
**「対象なのに出ない」と「対象外なのに出る」が同時に起きる。**

### いまやったこと

`src/etl_quality.py` の `age_contradictions()` で**検出して報告する**。
**止めない。** 元データ側の誤りで ETL を止める理由はなく、直せるのは自治体だけ。

### 決めていないこと

**矛盾したときにどちらを採るか。** この ADR を覆す（推定を優先する）判断になるため、
件数と内訳が見えるようになってから決める。判断材料としては次が要る。

- 10件が「元データの誤り」なのか「制度名の書き方が特殊」なのか
- 自治体に報告する経路があるか（オープンデータの問い合わせ先）

**件数が少ないうちは、個別に直すより見えるようにしておく方が安全**という判断。

## 変更するときの注意

ルールを足す・順序を変えるときは必ず `tests/test_age_rules.py` を通すこと。
特に「就学前が学齢より先」の順序を壊さないこと。

**実データで前後を比べること。** 上の +60件は、dev の全 7,812件に対して
変更前後のルールを両方走らせ、`新規 / 消失 / 変化` を数えて確かめている。
テストだけでは「既存の推定を壊していないか」が分からない
（今回も、最初の実装では 25件の新生児訪問が 0か月に狭まっていた）。


## 追記（2026-08-23）: `explicit` を無条件に信じない（issue #114）

この ADR は **「明示された年齢（`explicit`）を最優先し、推定で上書きしない」** と決めた。
その前提は「元データの年齢欄は正しい」ことだが、**実データでは成り立たない。**

```
三鷹市「3～4カ月児健康診査」   年齢欄 36〜71   ← か月を歳の欄に入れている
青梅市「5歳児虫歯予防教室」    年齢欄 5〜6     ← 歳を月の欄に入れている
```

そのまま使うと **0歳の子に4か月児健診が出ず、3〜5歳の子に出る。**
「対象なのに出ない」と「対象外なのに出る」が同時に起きるうえ、
探している人からは「無い」ようにしか見えないので気づけない。

**制度名から読めた範囲と重ならないときだけ**、制度名を採る（`age_source='corrected'`）。

- **重なっていれば元データを尊重する。** 少しのずれで上書きしない
- **元の欄は残す。** `min/max_age_months` は書き換えず、`effective_*` だけ差し替える
- **断定しない。** 画面には「（推定）」と出し、なぜその範囲なのかを補足で伝える。
  採らなかった判断はこちらのものであって、自治体が定めた条件ではない

prod 実測で11件（#141 の検出による）。元データ側の誤りなので、
**直るまでの当座の措置**という位置づけ。都への報告は別途。
