# ADR 0016: アクセシビリティの基準を axe で機械的に守る

- ステータス: 採用
- 日付: 2026-08-12
- 関連: issue #58

## 背景

行政サービスは「みんなの公共サイト運用ガイドライン」で **JIS X 8341-3:2016 の AA 準拠**
が求められる領域にある。デジタル庁デザインシステムを採用した（#33）以上、
見た目だけ借りて中身を担保しないのは筋が通らない。

それまで a11y を検証する仕組みは何も無かった。実際、**全ページで `<h1>` が1つも
出ていなかった**（後述）ことに誰も気づいていなかった。

## 決定

`axe-core` を E2E に組み込み、**違反ゼロを CI の必須条件にする**（`e2e/test_accessibility.py`）。

守る範囲は画面ごとに分ける。

| 画面 | WCAG 2.1 AA 相当 | best-practice |
|---|---|---|
| トップ / 詳細（自分たちで書いた画面） | **必須** | **必須** |
| 404 | **必須** | まだ見ない（後述） |
| `/debug`（移行期間中の旧画面。ADR 0014） | **必須** | 見ない |

axe のタグでは `wcag2a` / `wcag2aa` / `wcag21a` / `wcag21aa` を AA 相当として扱う。

## 理由

### なぜ既定のまま全部を必須にしないのか

axe の既定は `best-practice`（AA の要件ではない**助言**）も一緒に返す。
混ぜると「守るべき基準」と「あった方が良い助言」の区別がつかず、
落ちたときに直すべきかどうかを判断できない。**タグで明示的に分ける。**

### なぜ Next.js 側は best-practice まで必須にするのか

**導入時点でゼロだったから。** 緩める理由が無い。
ゼロのものをゼロのまま保つのは安いが、増えてから戻すのは高い。

それ以上に重要な理由がある。**下で挙げた「全ページに `<h1>` が無い」を検出したのは
best-practice であって AA ではない。**

```
[moderate] page-has-heading-one — tags: ['cat.semantics', 'best-practice']
```

h1 を元に戻して確かめると、**AA 側は通ってしまい best-practice 側だけが落ちる。**
つまり best-practice を必須にしていなければ、この不具合は見つかっていない。

「AA 準拠が目的なのだから best-practice は外そう」という判断は一見筋が通るが、
**具体的な実害（スクリーンリーダーの見出しジャンプが効かない）を捕まえているのは
best-practice の方**である。外すときはこの事実を踏まえること。

### なぜ 404 だけ best-practice を見ないのか

いま 404 に出ているのは **Next.js 組み込みの画面**（`404 This page could not be found.`）で、
こちらが書いたものではない。`<main>` を持たないため `landmark-one-main` と `region` が出る。

**#71 で `not-found.tsx` が入れば両方とも消える**ので、そのときに引き上げる。
それまでは AA だけを守る（AA はいまもゼロ）。

### なぜ `/debug` は AA だけなのか

`/debug` は素の JS で書かれた移行期間中の画面で、正式な画面ではない（ADR 0014）。
`landmark-one-main` / `region` の指摘が残っているが、**構造を作り直す投資はしない。**

一方 AA は譲らない。**実データの制度情報を出している画面**である以上、
「開発用だから読めなくてよい」とは言えない。

### なぜ静的検査だけにしないのか

axe が見るのは DOM であって、**操作できるかは分からない。**
マウスが使えない人にとって「対象制度が出ているのに申し込みページへ行けない」のは、
出ていないのと同じ。キーボードだけで一覧 → 詳細まで辿れることと、
フォーカスが視覚的に分かることを別途テストしている。

## 導入時に見つかったもの

### 全ページに `<h1>` が無かった

デジタル庁デザインシステムの `Heading` は**スタイル用の `<div>` を描画するだけ**で、
セマンティックな見出しは `HeadingTitle` が担う。両者を取り違えていたため、
**見た目は見出しなのにアクセシビリティツリーには何も無い**状態だった。

スクリーンリーダーの見出しジャンプが一切効かない。#71 のレビューで
「`Heading` が実際の見出し要素を出していない」と指摘されていた件で、
このとき初めて機械的に検出された。

### `/debug` の居住地セレクトに名前が無かった（critical）

`aria-label` を付けて対応。見出しの `<p>` は視覚的にはラベルに見えるが、
`<select>` と関連づいていなかった。

## 帰結

- 新しい画面を足すときは、この2つのファイルにページを追加する
- `axe-playwright-python` を `requirements-dev.txt` に追加した。
  **axe-core は同梱**されているので実行時に外部から取りに行かない
- 開発用コンテナのイメージ更新が要る（`make agent-up`）。
  入っていない場合は import 時に何をすればよいか出る

## 積み残し

- **色のコントラストは axe が「実際に描画された色」で見るため、ダークモードは別途必要。**
  いまはライト固定にしてある（#101 / #102）。#101 で対応するときは、
  `color_scheme="dark"` でも同じ検査を通すこと
- 属性入力フォーム（#53）が入ったら、ラベルとエラーメッセージの関連づけを追加で見る
- グラフ表示（#56）は視覚に依存するため、同じ情報をテキストでも提供する必要がある。
  axe では検出できないので、実装時に別途設計する
