| カラム | 型 | 備考 |

### 本文とリンク

| カラム | 型 | 備考 |
|---|---|---|
| `summary` / `description` / `utilization` | STRING | **リンク除去済み**の読みやすい本文 |
| `summary_raw` / `description_raw` / `utilization_raw` | STRING | 原文 |
| `related_links` / `form_links` / `embedded_links` | ARRAY\<STRUCT\<title, uri\>\> | リンク類 |

> 元データは本文中に `タイトル;https://...` という独自形式でリンクを直接埋め込んでいます
> （平均 4.5 リンク/レコード）。`extract_links()` で全テキスト列から分離しています。
> **テキスト列を追加するときも必ずこの処理を通してください。**

タイトルの切り出しは `EMBEDDED_LINK_RE`（`src/etl_normalize.py`）で、
**改行・句点・パイプ（表組みのセル境界）を境界**にしています。空白では切りません。

- 空白で切ると「傷病届 (PDFファイル: 30.5KB);URL」が `30.5KB)` になる（実データの4.1%で発生していた）
- 句点で切らないと、日本語の本文は空白で区切られないため直前の文まで飲み込む（同 4.1%）
- 区切りが無い場合は「詳しくは」のような導入句もタイトルに入る。
  **サイズ表記の断片になるよりは害が小さい**という判断（issue #80）
- タイトルが**裸のURLそのもの**になった場合は捨てて `None` にする。表示名として意味が無いため。
  API 側（`app/routers/benefits.py` の `_links`）が uri を表示名に使うフォールバックに乗る

dev の実データでの計測（タイトル側だけを変えた時点。issue #80。この時点のリンク総数は 36,632）:

> 以降の URL 側の修正（issue #86）でリンク総数は変わります。**この表と下の表は
> 別々の時点で測ったもの**なので、総数（36,632 / 35,122 / 33,698）は突き合わせられません。

| 指標 | 旧 | 新 | 新＋URL除外 |
|---|---|---|---|
| サイズ表記の断片だけ | 1,516 | 15 | 15 |
| 直前の文を飲み込み（句点あり） | 1,495 | 0 | 0 |
| タイトルが助詞で始まる（文の途中から） | 356 | 249 | 248 |
| タイトルに `http` を含む | 43 | 54 | **35** |
| タイトル全体がURL | 18 | 19 | **0** |
| リンク検出数 | 36,632 | 36,632 | 36,632 |

#### URL 側（`;` の右）の終端規則

元データは **URL の直後に本文や次のリンクが空白なしで続く**ため、空白だけを終端に
していると URL が本文を飲み込みます（issue #86）。次の3段構えで切っています。

1. **区切り文字で止める**（正規表現側）。空白・パイプ・全角/半角括弧に加え、
   `;` `,` `、` `・` `。` `<` `>`。
   **`;` を含めるのが重要**で、これが無いと `A;url・B;url・C;url` が1本の URI に潰れ、
   2件目以降がリンクからも本文からも消えます
2. **ひらがなで止める**（`trim_uri()`）。URL のパスに使われる日本語は名詞（漢字・カタカナ）で、
   助詞のひらがなはまず現れません。`…/産後ケアよりお申し込みください` の「より」以降を落とします
3. **非ASCIIの記号・約物で止める**（同上）。`」`（456件）`¥`（165件）`＜`（104件）`【`（19件）など。
   Unicode のカテゴリが `L`（文字）/ `N`（数字）以外なら本文とみなします

**非ASCII を一律に切ってはいけません。** `https://…/診療科-部門紹介/妊婦健診産後ケア/` の
ように**パス全体が日本語の正当な URL** が実在します。上の2・3が文字と約物を区別しているのは
このためです。漢字だけが続く `…/jikan.html等` は区別できないので、
**ファイルの拡張子より後ろに非ASCIIが来たら拡張子までで切る**という規則を足しています
（`#anchor` を壊さないよう、この規則はひらがな・約物では適用しません）。

切り落とした部分は**捨てずに本文へ戻します。** 「本文の内容はリンクの取り方に影響されない」
という性質を保つためです。

dev の実データでの計測（issue #104 で ETL を実行した後の実測値。「旧」は実行前の dev）:

| 指標 | 旧 | 新 |
|---|---:|---:|
| URI に非ASCIIが混入 | 5,236 | **40** |
| URI にひらがなが混入 | 4,396 | **0** |
| URI に URL が2本以上（archive.org・クエリ内 URL を除く） | 296 | **6** |
| リンク総数 | 35,122 | **33,698** |
| 壊れた URI を持つ制度 | 1,847 | **26** |

**リンク総数は増えるのではなく 1,424件減ります。** `;` を終端に足したことで
1本に潰れていたリンクが分割されて増える分（URL が2本以上入っていたもの 852 → 542）より、
**正しい URL に揃った結果、制度内で重複排除されて畳まれる分**の方が大きいためです。
`embedded_links` は制度ごとに URI で重複排除しており（`src/etl_graph.py`）、
壊れた URI は末尾に飲み込んだ本文が違うぶん別物として残っていました。

残る40件（ユニーク27件）は、上記の正当な日本語 URL と、
`…/JwcKfBU8Ek9NnQpk6窓口` のように漢字・カタカナだけが続いて機械的に区別できないものです。

## 更新手順

```bash
make etl      # 取得 → 整形 → 品質チェック → ロード（WRITE_TRUNCATE で全置換）
```

### 品質チェック（`src/etl_quality.py`）

元データは都が更新するもので、こちらの都合とは無関係に構造が変わりうる。
`transform()` は例外を投げずに「空のテーブル」や「全部 NULL の列」を作れてしまうため、
**ロードの前に**次を確認し、基準を外れたら書き込まずに ETL を落とす。

| 見るもの | 基準 | 根拠 |
|---|---|---|
| 各テーブルが空でないこと | 1件以上 | 0件のロードは全消しと同じ |
| 件数の急減 | 前回比 **30%** 減まで | 一度に3割消えるのは取得か整形の失敗を疑う |
| 必須列の欠損（`benefits`） | `benefit_id`/`title`/`scheme_id` は **0%**、`area_code` 5%、`description`/`summary` 10% | 実測値（`description` は 2.7%、他は 0%）に余裕を持たせた |
| 必須列の欠損（`statuses`） | `status_id`/`name`/`type` は **0%** | 実測 0%。欠ければ条件ノードとして成立しない |
| 必須列の欠損（`documents`） | `doc_id`/`doc_name` は **0%** | 実測 0%。同上 |
| `age_source='unknown'` の比率 | **45%** まで | 実測 34.2%。跳ね上がったら `age_rules.py` が元データの表現変更に追従できていない |
| 自治体数 | **55** 以上 | 実測 63 |

前回件数は**いま BigQuery に入っているデータそのもの**から読む
（直前の ETL 結果がそこにあるので、専用のメタテーブルは持たない）。
初回実行でテーブルが無いときは件数比較を飛ばす。

**チェックをロードの前に置いているのは意図的。** `load_tables()` はテーブルごとに
`WRITE_TRUNCATE` するため、途中で落ちると「benefits だけ新しく statuses は古い」という
中途半端な状態が残る。書く前に落とせばその状態自体を作らずに済む。

しきい値は `src/etl_quality.py` の定数。元データの正当な変化で落ちるようになったら、
**しきい値を緩める前に、まず変化が正当かを確認すること。**

#### 止めずに報告するもの: 制度名と年齢欄の矛盾（issue #114）

上の表は**落とす**基準だが、`age_contradictions()` だけは**報告するだけ**で ETL を止めない。
元データ側の誤りであり、直せるのは自治体だけなので、こちらのロードを妨げる理由がないため。

制度名から年齢が読める `explicit` な制度で、その年齢が `min/max_age_months` と
**まったく重ならない**ものを挙げる。dev の実測は **10件**。

```
三鷹市  「3～4カ月児健康診査」  年齢欄 = 36〜71   ← か月を歳として登録している
三鷹市  「6～7カ月児健康診査」  年齢欄 = 72〜95
目黒区  「9から10か月児健診」   年齢欄 = 6〜7     ← 概要にも「9か月から10か月児」とある
青梅市  「5歳児虫歯予防教室」   年齢欄 = 5〜6     ← 歳を月として登録している
武蔵村山市「2歳児歯科健康診査」  年齢欄 = 〜23     ← 2歳児が対象外になる
```

> ⚠️ **`effective_*` は `explicit` を最優先するので、誤った年齢欄がそのまま判定に使われます。**
> 三鷹市の例では **0歳の子に3〜4か月児健診が出ず、3〜5歳の子に出ます。**
> 「対象なのに出ない」と「対象外なのに出る」が同時に起きている状態です。
> #61 で対象年齢を画面に出すようにしたため、**利用者にも誤った範囲が見えます。**

**完全一致は求めていません。** 境界のずれ（`1歳6か月児健診` の年齢欄が 19〜23 など）まで
挙げると数が多くなり、本当に危険なものが埋もれるためです。重なりがゼロのものだけを見ます。

どちらを採るか（元データか制度名か）は**まだ決めていません。** ADR 0002 が
「明示値を推定で上書きしない」と定めており、覆すなら ADR の改訂が要ります。
